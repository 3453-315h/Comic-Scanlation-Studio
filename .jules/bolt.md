## 2024-05-24 - Connection Pooling in Worker Threads
**Learning:** In this application's architecture, translations are often run inside short-lived worker threads (via `BatchProcessor` or asynchronous tasks) which create new asyncio event loops. While we must avoid caching asyncio-dependent clients (like `googletrans`) across these threads to prevent event loop thread-safety issues, synchronous clients like `requests.Session()` (used by DeepL) and the OpenAI client are perfectly safe to reuse and pool. Re-instantiating them for every single text bubble in a chapter creates significant overhead from repeated TLS handshakes.
**Action:** Always instantiate and reuse synchronous HTTP clients at the class level (`__init__`) instead of inside the method being called in a loop, but leave asyncio-based clients to be instantiated per-call or per-thread if event loop safety is a concern.
