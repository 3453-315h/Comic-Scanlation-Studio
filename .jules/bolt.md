## 2025-02-28 - TLS Handshake Overhead in Translation API Clients
**Learning:** Each call to `requests.post()` or `OpenAI(api_key=...)` creates a new HTTP connection, resulting in a full DNS resolution and TLS handshake. In batch processing (like translating many comic bubbles), this network overhead becomes a significant bottleneck, multiplying API latency by 2x-3x. Furthermore, caching `googletrans.Translator` or other asyncio-based wrappers on the `Translator` object causes event loop thread-safety errors because translations happen in short-lived `WorkerThread`s which instantiate new loops, but synchronous clients like `requests.Session` and the synchronous `openai.OpenAI` client are safe to pool per `Translator` instance.
**Action:** Always instantiate connection pooling tools (like `requests.Session()`) or reuse synchronous client instances in the `__init__` constructor when making external API calls in loops or batch processing to reuse existing HTTP/TLS connections.
