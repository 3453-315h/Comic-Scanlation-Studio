## 2024-05-18 - Improve translation network calls performance
**Learning:** Making repeated API calls (DeepL, OpenAI) without connection pooling results in a huge performance bottleneck due to repeatedly establishing TLS handshakes. In Python, `requests.post()` creates a new connection each time. Also, OpenAI client recreates the `httpx` client each time it's instantiated.
**Action:** Use `requests.Session()` for DeepL API calls. Instantiate the `OpenAI` client once and reuse it across requests to reuse its internal `httpx` connection pool. Since `requests.Session()` is not thread-safe, we should use lazy initialization if `Translator` instances are shared across threads, or just initialize it lazily per-instance (if each worker thread creates its own `Translator`, `requests.Session` can just be instantiated lazily in the translation methods, or as a property, avoiding pickling issues if passed between processes).
