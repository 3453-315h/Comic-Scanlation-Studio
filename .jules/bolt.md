## 2024-06-25 - Translation API Connection Pooling
**Learning:** For batch translation tasks in loops (like processing multiple comic bubbles on a page), creating a new HTTP connection or OpenAI client per translation results in massive performance overhead from repeated TLS handshakes. However, since the application runs these background tasks inside short-lived WorkerThread instances (meaning each task gets a new asyncio event loop), we must be careful. We can safely pool synchronous clients (like `requests.Session` and standard `OpenAI`) across tasks, but must NOT cache asyncio-dependent clients (like `googletrans.Translator`) across threads to avoid event loop thread-safety issues.
**Action:** When making external API calls in loops or batch processing, always use connection pooling (like `requests.Session()` or reusing synchronous client instances) to prevent repeated TLS handshakes, but strictly avoid this optimization for asynchronous clients that depend on event loops in a multi-threaded context.
