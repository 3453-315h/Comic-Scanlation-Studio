## 2024-09-11 - Connection Pooling in Multi-threaded Translators
**Learning:** In applications using WorkerThreads that create new asyncio event loops per task, caching asyncio-dependent clients (like `googletrans.Translator`) across threads causes thread-safety issues. However, synchronous HTTP clients (like `requests.Session` for DeepL or the `OpenAI` client) are thread-safe and SHOULD be pooled to prevent redundant TLS handshakes for every API call in a batch, especially since we iterate over many text bubbles per page.
**Action:** Always instantiate `requests.Session()` or reusable API clients (e.g. OpenAI) inside the module initialization or lazy-load them on first use, instead of repeatedly instantiating them inside the processing loop, ensuring we don't accidentally cache asyncio-dependent components.
