## 2024-08-07 - Optimization: Connection Pooling for DeepL/OpenAI
**Learning:** External API backends like DeepL and OpenAI perform a TLS handshake per translation request in the comic processing loop. This adds roughly ~200-500ms of overhead per text bubble in standard usage. When worker threads process multiple bubbles, reusing a client context (`requests.Session` or an `OpenAI` client instance) is critical to avoiding this bottleneck. However, we intentionally omitted caching for `googletrans.Translator` since it involves asynchronous I/O and asyncio event loop threads, which causes errors if reused across PySide6 worker threads.
**Action:** Always instantiate HTTP clients with `Session` objects or equivalent reused instances inside loop-heavy background threads, but carefully verify thread safety for async libraries.
