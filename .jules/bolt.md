## 2024-09-09 - Connection Pooling for API Clients in Worker Threads
**Learning:** In a desktop application making repeated external API calls (e.g. DeepL, OpenAI) inside short-lived async worker threads or loops, repeatedly initializing clients causes a new TLS handshake on every translation request. This introduces significant latency per translation, which quickly accumulates in batch operations. Asyncio-dependent clients (like `googletrans.Translator`) cannot be cached globally due to event loop thread-safety issues, but synchronous clients (`requests.Session`, `openai.OpenAI`) CAN be cached per instance.
**Action:** When working with synchronous external HTTP APIs in loops or batch processing, always use connection pooling (like `requests.Session()` or a reused `OpenAI()` client) to persist connections across requests, preventing redundant TLS negotiations and substantially improving throughput.
