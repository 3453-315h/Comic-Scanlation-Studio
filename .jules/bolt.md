## 2024-05-20 - Connection Pooling for External Translation APIs
**Learning:** External APIs like DeepL or OpenAI might be repeatedly called inside a loop over multiple texts within a single pipeline stage. Without connection pooling, each translation request establishes a new TCP and TLS connection, adding significant latency per text bubble (often hundreds of milliseconds).
**Action:** Use a `requests.Session()` object instead of `requests.post()` for DeepL API calls. Similarly, initialize and store the `openai.OpenAI` client in the `Translator` object `__init__` rather than re-creating it inside `_openai_translate` on every call. Note: Do not share `googletrans.Translator()` or other `asyncio`-tied components between threads, but regular HTTP connection pooling in `Translator` is safe and highly beneficial for multiple synchronous requests sequentially executing on the worker thread.
