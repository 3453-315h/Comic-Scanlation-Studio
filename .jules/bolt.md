## 2024-06-25 - Translators Pool Reusing TLS Connections
**Learning:** In the `Translator` class, making separate `requests.post` or initializing new `OpenAI()` clients for every single translated text block caused massive overhead due to repeated TLS handshakes. However, since the application runs translations inside short-lived `WorkerThread` instances (each creating a new `asyncio` event loop), we cannot cache `asyncio`-dependent clients (like `googletrans.Translator`) across threads safely.
**Action:** Always use connection pooling (e.g., `requests.Session()` or reusing the `OpenAI` client instance) for synchronous external API calls in loops or batch processing, but avoid caching `asyncio`-dependent clients across different event loops in this specific thread-based architecture.
