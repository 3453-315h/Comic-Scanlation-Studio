## 2025-02-14 - Connection Pooling for Translators
**Learning:** In a batch processing architecture like `BatchProcessor` that creates many sequential background tasks, clients doing REST API calls (like DeepL or OpenAI) can experience significant overhead due to repeated TLS handshakes for each text bubble. `asyncio` based clients (like `googletrans`) require careful lifecycle management to avoid event loop thread-safety issues, but synchronous clients (`requests`, `OpenAI`) can and should be pooled using their native session mechanisms (`requests.Session()`, reusing `OpenAI()` client) across the lifetime of the `Translator` instance.
**Action:** Always verify if a third-party API client maintains a connection pool under the hood and initialize it once at the class/module level rather than re-instantiating it for every batch item to avoid TLS handshakes.
