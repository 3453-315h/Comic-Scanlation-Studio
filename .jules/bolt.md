## 2024-08-25 - Connection pooling for synchronous clients in WorkerThread architecture
**Learning:** The application uses short-lived `WorkerThread` instances, each creating a new `asyncio` event loop. This means `asyncio`-dependent clients (like `googletrans.Translator`) shouldn't be cached across threads. However, synchronous clients like `requests.Session` (used for DeepL) and `openai.OpenAI` are safe to cache and pool across translations, significantly reducing the overhead of repeated TLS handshakes during batch API translation loops.
**Action:** When working in this application, carefully distinguish between synchronous clients (which should be pooled) and asynchronous clients (which should be instantiated per thread or managed properly to avoid event loop thread-safety issues).
