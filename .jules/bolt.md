## 2024-05-18 - Client Connection Pooling in Worker Threads
**Learning:** External API clients (e.g., DeepL with `requests`, OpenAI client) were being recreated on every translation call within short-lived `WorkerThread` instances, causing repeated, expensive TLS handshakes (bottleneck). Furthermore, although asynchronous clients cannot be shared due to distinct `asyncio` event loops across worker threads, synchronous clients can be safely pooled and reused within those threads.
**Action:** Use connection pooling (like `requests.Session()` or a single instance of `OpenAI()`) for synchronous external API calls to avoid repeated TLS handshakes, maintaining them lazily as instance variables. Ensure we don't cache asyncio-dependent clients across the app if they might run in different short-lived worker threads.
