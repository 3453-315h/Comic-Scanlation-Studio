## 2024-06-25 - Connection pooling for external API clients
**Learning:** In a batch-processing application, instantiating a new `requests.post` or `OpenAI()` client per translation adds substantial TLS handshake overhead and network latency. Additionally, this app's architecture uses short-lived WorkerThread instances, so caching asyncio-dependent clients (like `googletrans.Translator`) across threads will cause event loop thread-safety issues.
**Action:** When making external API calls in loops or batches (like DeepL or OpenAI), lazy-load and cache the client instance (`requests.Session()` or `OpenAI()`) on the worker/module instance to ensure connection pooling. Avoid doing this for `googletrans` or other libraries that intrinsically bind to the thread's event loop to prevent `RuntimeError: This event loop is already running`.
